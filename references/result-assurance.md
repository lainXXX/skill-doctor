# 结果保证协议(result-assurance)

被 skill-doctor 阶段 F(Result Assurance)与阶段 ③ 深度模式加载。**定位**:回答"声称的结果是否有证据证明成立"。
不是 formal verification——LLM 输出非确定、外部工具变化、用户上下文影响,不可自动证明。因此命名 **Assurance(保证)**,不用 **Verification(验证)**。

## 1. 检查项(R1-R8 默认;R9-R10 仅沙箱)

| ID | 检查项 | 检查问题 | 客观破坏项(→ 拉低健康) |
|----|--------|----------|------------------------|
| R1 | 输出契约保真度 | SKILL.md 声明输出格式(JSON schema/模板/文件类型)与实际产出结构、字段、类型是否一致? | 示例不可解析 |
| R2 | 步骤链可喂性 | step N 输出能否喂给 step N+1(类型匹配/字段依赖/文件路径一致)? | 步骤断链 |
| R3 | 脚本韧性 | 正常路径(exit code/stdout-stderr/输出文件/耗时)+ 超时 + 降级熔断 + 错误友好 + 退出码是否做好? | 缺脚本/语法错误/失败仍 exit 0 |
| R4 | 文档-执行一致性 | SKILL.md 描述流程与实际调用链一致(跳过声明步骤/多出未声明步骤/顺序漂移)? | — |
| R5 | 副作用诚实性 | 所有副作用(文件写删/网络/环境变量)是否诚实声明,且有清理回滚? | 未声明危险副作用 |
| R6 | 依赖与环境契约 | 依赖声明完整且版本锁定;所需环境变量/工具是否说明? | 依赖缺失声明 |
| R7 | 输入边界与拒绝路径 | 非法/缺失/恶意输入是否有明确拒绝路径(非静默吞掉或崩溃)? | — |
| R8 | 可观测性与测试资产 | 有黄金样例/复现命令/日志可观测性(否则后续验证无据)? | — |
| R9* | 幂等性/确定性 | 同输入多次运行输出是否稳定? | — |
| R10* | 上下文吞吐退化 | 长输入是否 token 爆炸/退化? | — |

\* R9/R10 需真实重复运行,默认不评估;仅在 E4 沙箱实跑时启用。

## 2. 证据等级阶梯(E0-E4)

| 等级 | 方式 | 默认性 | 置信度上限 | 能说 | 不能说 |
|------|------|--------|-----------|------|--------|
| E0 | 声明复核(只读 SKILL.md) | 默认 | Low | 复述声称 | 任何行为证据 |
| E1 | 静态审计(读 scripts/references/config;AST/正则/模式匹配) | 默认 | Medium | "未发现声明与实现明显矛盾" | "可运行" |
| E2 | 干跑探针(bash -n/schema 校验/依赖存在性/步骤 DAG 断链) | opt-in 低风险 | Medium-High | "静态结构自洽" | 行为正确 |
| E3 | 证据审查(审用户/CI 执行证据包:日志/实际输出/失败记录;含 skill 自带 test-cases 只读验证) | opt-in 只读 | High(受证据质量限制) | "基于真实执行证据的审查" | 超出证据覆盖 |
| E4 | 沙箱实跑(隔离执行 + 故障注入:超时/断网/缺输入/权限拒绝) | opt-in 显式授权 | High(限沙箱用例) | "沙箱用例内通过" | "生产可运行" |

**无证据 ≠ 失败**:缺 E3/E4 证据只降低"执行可信度",不直接拉低健康等级。

## 3. 逐条声明与诚实标注(写死)

每条 Result 结论输出固定 schema:

```
R<n> 判定(PASS/不足/FAIL/⚠️ 无证据)
evidence_level: E0-E4
confidence: Low / Medium / Medium-High / High
verified_by: 静态审计 / 干跑探针 / 证据审查 / 沙箱实跑
not_verified: 说明未覆盖部分(如"条件分支未覆盖""沙箱未含生产变量")
```

- 静态(E0/E1)结论必须带注:**"基于代码结构审查,未执行实际运行"**
- 沙箱(E4)结论必须带注:**"在受控沙箱中执行;沙箱边界 = 网络阻断/文件系统只读/超时 30s"**
- 未做任何 L4 检查的 skill → Result Assurance:⚪ 未验证,标注"结果未经验证,请谨慎信任输出一致性"
- 静态通过但未实跑 → 🟡 Static Passed(Runtime Not Tested)
- 沙箱用例内通过 → 🟢 Runtime Verified
- 纯 Markdown skill(无可执行脚本)→ R3/R7/R9/R10 判 ⚠️ 不适用,并标注"无脚本可执行"

## 4. 对双结论的影响

- 客观破坏项(R1/R2/R3/R5/R6 表中"→ 拉低健康"列)命中 → 拉低健康等级;R3 缺脚本/语法错误/失败仍 exit 0 → 直接 🔴
- 缺执行证据(E2-E4 未跑)→ 只降低执行可信度,**不拉低健康等级**
- ⭐⭐⭐ 优秀度要求具备 E2/E3 证据;纯 E0/E1 最多 ⭐⭐;**纯 Markdown 无脚本可用 E3-MD 真实使用产物证据达 ⭐⭐⭐;元工具类纯 Markdown 可暂获 ⭐⭐+「设计卓越」过渡标识(细节见 stars.md,仅纯 Markdown / 元工具分支加载)**
- R9/R10 未评估不扣分,标注"opt-in 未启用"

## 5. 沙箱授权声明(E4 前置,写死)

开启 E4 前,输出以下声明并等待显式确认:

```
深度体检将在隔离容器中真实执行该 skill 的命令。
- 所有网络请求将被拦截(除非显式 --allow-network)
- 仅允许写入临时目录,主机文件系统只读
- 最大内存 512MB,超时 30s
- 不会修改任何系统配置
是否继续?[y/N]
```

执行完成后,报告必须列出:实际运行命令、注入故障类型、沙箱异常绕过行为(如有)。

## 6. 单模型局限声明(报告末尾固定)

```
⚠️ 本评估由 AI 模型自动生成,可能存在误判或遗漏边缘情况。
L4 动态验证受限于沙箱环境,无法完全复现真实生产场景。
结论仅供质量参考,不可替代人工 code review 与集成测试。
```

## 7. 评估卫生

- 静态审计只读文件,不执行任何被评估命令
- E2 干跑只做解析/存在性检查,不触发 skill 行为
- 沙箱不可用(Docker/Firecracker 缺失)→ 自动降级 E1,报告标注"环境不支持深度验证",不阻塞
- 报告标注评估方式(自评/交叉验证)与运行模型

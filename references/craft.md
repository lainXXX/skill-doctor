# 写作工艺清单(craft)

被 skill-doctor 阶段 G(Craft 写作工艺)加载。**定位**:评估 SKILL.md 作为指令文本的**可预测性**("同一过程、每次同结果"能否由文本结构保证)。与阶段 E(Quality)互补:Quality 问「优秀吗」(12 条),Craft 问「写得可预测吗」。
原则来源:writing-great-skills。C1-C5 均为 Should 级,AP11-AP15 机械命中降为证据探测器映射入本清单(对称于 quality-rubric 的 AP1-AP10 映射)。**Craft 只作报告维度,不进健康/星级公式。**

## 判定守则(写死,防确认偏误)

1. **先找不足再找优点**:先扫描重复措辞/否定式禁令/模糊判据/无操作行,再找亮点
2. **证据可证伪**:正面证据须满足「删掉该行评分会下降」;不满足则该证据不采信
3. **置信度 ≤ Medium**:主观判断不装确定;无行号证据 → ≤ Low
4. **固定 schema**:每条输出 `C<n> | 判定 | 证据行号 | 支持理由 | 反对理由 | 置信度`;禁止自由散文
5. **No-Op 测试**:对疑似无操作行单独执行「删掉行为变不变」;不变 → 判 AP12 命中

## 校准锚点(known-good / known-bad)

- **🟢 优秀锚点**:一处锚点词取代多处重述;步骤判据可核查+穷尽;禁令仅留硬护栏且配正面替代;低频引用压到 references/ 下、顶层可读;每条含义单源
- **🔴 平庸锚点**:否定式禁令堆叠(「不要…」「别…」);同一规则多处改写;步骤无完成判据;SKILL.md 顶层塞满全部细节

## C1-C5 写作工艺标准(均 Should)

每条固定格式:`检查问题(是/否/无法评估) | 好示例 | 坏示例 | 修复方向 | 证据引用 | 级别`

### C1 锚点词 Leading Word
- **检查**:同一质量/约束是否被多处措辞重述,而非塌缩为一个预训练紧凑词?
- **好/坏**:好=一处 _tight_ 锚住「快速/低开销/确定性」;坏=「确保快速完成」「保持低开销」「务必确定性」三处各自表述
- **修复**:找到重述群 → 塌缩为单一锚点词,其余处引用该词
- **级别**:Should。证据:GLOSSARY「Leading Word」——紧凑预训练概念,一处定义多次复用,锚定整片行为,最省 token

### C2 正向引导 Negation
- **检查**:指令是否说「该做什么」而非「不要 X」?禁令是否仅留无法正面表述的硬护栏、且配替代行为?
- **好/坏**:好=_relentless_ 取代「不要偷懒」;坏=「不要省略步骤」「别写多余代码」堆叠(提到 X 反让 X 更可用)
- **修复**:正向化——写下目标行为;仅在安全/数据损失硬边界保留禁令
- **边界**:A3(Quality)=约束**是否**存在;C2=约束**如何措辞**(正向 vs 否定)。B. Structure 指令冲突=指令间矛盾;C2=单条表述风格
- **级别**:Should

### C3 完成判据 Completion Criterion
- **检查**:步骤/阶段是否以**可核查+穷尽**的完成判据收尾(agent 能区分做没做完)?
- **好/坏**:好=「每个改到的模型都记入」;坏=「生成变更清单」(不可核查是否穷尽)
- **修复**:判据改写为可核查、穷尽;无法判定 → 提示过早完成风险
- **边界**:O3(Quality)=输出验收判据(用户知道做对没);C3=步骤级完成判据(agent 运行中知道做没做完)
- **级别**:Should

### C4 信息层级与渐进披露 Progressive Disclosure + Co-location
- **检查**:低频引用是否压到上下文指针下、顶层保持可读?相关概念是否共置?
- **好/坏**:好=SKILL.md 只留每分支都要的,细节进 references/ 由「加载 references/X.md」按需打开;坏=顶层塞满全部细节(Sprawl)
- **修复**:按使用频率下压——内联每分支都需的,指针化仅某些分支用到的
- **假披露测试**:该引用是否**所有模式都加载、无分支跳过**,且其内容已在 SKILL.md 表述过?两者皆是 → 文件拆分只省维护、不省上下文 = 假披露(Sprawl 证据),C4 判不足
- **边界**:D. Brevity=行数档位(<200/200-500/>500);C4=披露结构(什么被压下去、顶层留什么)
- **级别**:Should

### C5 单源无重复 Single Source of Truth
- **检查**:每条含义是否仅一处权威来源,他处只做指针引用?
- **好/坏**:好=规则一处定义,他处「见 X §N」;坏=同一规则在正文+参考+输出模板三处改写,改一处漏两处
- **修复**:收窄到单源,他处改指针
- **边界**:AP7=职责混杂(宣称 X 含 Y 流程);C5=同义重复(同一含义写两遍)
- **级别**:Should

## AP11-AP15 证据探测器映射(机械命中即证据)

| AP | 对应标准 | 说明 |
|----|----------|------|
| AP11 重复 | C5 | 同义内容 ≥2 处 → C5 不足/FAIL 的证据 |
| AP12 无操作行 | 直接修复 | 删行行为不变 → 直接删除,不映射 C 判据 |
| AP13 否定式 | C2 | 非硬护栏禁令 → C2 不足/FAIL 证据 |
| AP14 过早完成 | C3 | 判据模糊 → C3 不足/FAIL 证据 |
| AP15 沉积 | ⚠️ 需作者确认 | 静态难判,不自动拉低 C 判据 |

## 判定分级

- `PASS / 不足(提及但泛泛) / FAIL / ⚠️无法评估`(缺证据不推断)
- Craft 整体:输出 `C1-C5 → N 通过 / M FAIL`,与 Health/Excellence 并列但**独立**,不合并进健康/星级
- 勾完强制答「若只改一行写作,哪里最提升可预测性」;答不出 → Craft 判「表面通过」

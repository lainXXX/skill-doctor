# 优秀标准清单(quality-rubric)

被 skill-doctor 阶段 E(Quality)加载。**唯一判断型维度**:评估 skill 的"优秀度",而非机械检查"没坏"。
机械检查(L1)负责"没坏",本清单负责"是否优秀";AP1-AP10 降为证据探测器映射入本清单,不在清单外另设评分中心(AP11-AP15 属写作工艺维度,映射见 craft.md)。

## 判定守则(写死,防确认偏误)

1. **先找不足再找优点**:默认大多数初版 skill 平庸,先扫描失败点/冗余/模糊决策,再找亮点
2. **不看 name/description 自我标榜**:遮蔽名称与"大师级/完美/最牛"等自夸词,只评指令正文
3. **每维强制反证**:每个"强/中"必须回答"什么证据可能证明它其实更弱";无反证 → 降档
4. **证据可证伪**:正面证据须满足"删掉该行评分会下降";不满足则该证据不采信
5. **置信度 ≤ Medium**:主观判断不装确定;无行号证据 → ≤ Low
6. **固定 schema**:每条输出 `ID | 判定 | 证据行号 | 支持理由 | 反对理由 | 置信度`;禁止自由散文
7. **复现协议**:报告标注 rubric 版本 / 评估模型 / 评估温度(固定低值),保证同一输入可复现
8. **校准锚点**:对照下节好/坏锚点做相对判断(相对排序比绝对打分稳定)

## 校准锚点(known-good / known-bad)

- **🟢 优秀锚点**:description 含明确 what+when+not-when;步骤有序号、每步有输入/输出;歧义点有询问分支、高风险有停止条件;输出有固定模板 + 验收判据 → 12 条全过
- **🔴 平庸锚点**:description 泛泛("帮你做高质量 X");正文是大段描述性建议,无步骤、无分支、无输出契约 → 多数 FAIL

## 12 条标准(4 维 × 3 条)

每条固定格式:`检查问题(是/否/无法评估) | 好示例 | 坏示例 | 修复方向 | 证据引用 | 级别(Must/Should)`

### 维度一:有效性 Effective
- **E1(Must)** 单一核心职责?好:"自动生成数据库 migration 方案"。坏:"帮助完成各种开发工作"。
- **E2(Must)** description 覆盖真实表达、可稳定触发?证据 = 触发实验 must-hit 覆盖率。
- **E3(Should)** 承诺能力与实际能力一致(契约一致性,防过度承诺)?坏:description 声称能 X,正文实际只做 Y。

### 维度二:判断力 Judgment
- **J1(Must)** 明确不适用场景与触发边界(何时用/何时不用)?
- **J2(Must)** 与相似 skill 可区分、候选池不误触?证据 = 触发实验 near-miss 误触率。
- **J3(Should)** 失败/异常有降级(缺文件、权限不足时怎么办)?

### 维度三:Agent 适配性 Agent Fit
- **A1(Should)** 明确行动顺序(step 有序、每步有输入输出)?
- **A2(Should)** 依赖工具/文件/命令可被 Agent 获得(引用存在、路径合法)?
- **A3(Must)** 有行为约束而非"认真分析"(能改变 Agent 行为,不只普通文档)?

### 维度四:可操作性 Actionable
- **O1(Must)** 输入/输出契约明确?
- **O2(Should)** 输出可直接执行(步骤/代码/模板)?
- **O3(Should)** 有验收判据(用户能知道"做对了没")?

## 判定分级

- `PASS / 不足(提及但泛泛) / FAIL / ⚠️无法评估`(缺证据不推断;**Must 项 ⚠️ 不可判绿**)
- 每条输出证据引用;无证据不默认通过
- "Must 全过"口径:**PASS 与 不足 均算过**;FAIL 或 ⚠️ 不算

## AP 证据探测器映射

AP1-AP10 机械命中即某标准 FAIL 的证据,不在清单外另设评分中心:

| AP | 对应标准 | AP | 对应标准 |
|----|----------|----|----------|
| AP1 无限删除 | J3(降级/边界) | AP6 递归无边界 | A2(可获性) |
| AP2 裸 curl|bash | J1(边界) | AP7 职责混杂 | E1(单一职责) |
| AP3 敏感读取 | J3(边界) | AP8 无失败分支 | J3(降级) |
| AP4 无输入验证 | A2(可获性) | AP9 过宽匹配 | E1/A2 |
| AP5 硬编码密钥 | A2(可获性) | AP10 输出不稳定 | O3(验收) |

## 整体判断层(有否决权)

12 条勾完强制回答 3 问:
1. 这个 skill 最尖锐的用途是什么?
2. 最可能被误用/误触发的场景是什么?
3. 若只能改一处,哪里最能提升质量?
回答不出 → 清单只是表面通过。**整体判断负面 → 健康等级强制降 🟡**。

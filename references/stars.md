# 优秀度证据路径(stars)

被 skill-doctor 阶段 F(Result Assurance)追加加载——**仅当被评估 skill 为纯 Markdown(无脚本)或元工具类**时打开;脚本 skill 评估不加载。定位:⭐⭐⭐ 的证据如何拿到(§1 E3-MD 真实使用产物证据)与元工具过渡标识(§2 设计卓越)。证据形式可适配,证据门槛不能取消。

## 1. 纯 Markdown skill 的 E3 证据路径(E3-MD)

纯 Markdown skill(无独立可执行脚本,行为发生在消费端:宿主 agent 遵循 SKILL.md 指令执行)**不豁免证据要求**,但允许用**真实使用产物证据(E3-MD)** 满足 E3,从而可达 ⭐⭐⭐。证据形式可适配,证据门槛不能取消。

### 1.1 E3-MD 最低证据包(每案例)

| 字段 | 要求 |
|------|------|
| skill 版本 | 锁定版本:commit hash / tag / 版本号 |
| 使用场景 | 该 skill 被用于什么任务 |
| 输入材料 | 任务提示、上下文文件、需求描述(可脱敏) |
| 使用方式 | agent 或用户如何调用/引用该 skill |
| 输出产物 | 完整报告、代码、文档、审查意见、对话记录 |
| 验收标准 | 预先定义该产物为什么算合格 |
| 复核者 | 谁确认产物真实、有效 |
| 独立性 | 是否来自非作者、不同项目或真实用户 |
| 安全与隐私 | 已脱敏,不含密钥、敏感路径、私有数据 |

### 1.2 定量达标线(满足任意 2 项即认定 E3)

| 证据类型 | 具体要求 |
|---------|----------|
| 真实运行产出审计 | ≥3 份不同场景完整运行记录(输入+完整输出+执行链路),核验输出 100% 遵循文档指令/流程/约束,边界 case 符合预期 |
| 稳定性复现验证 | 独立执行 ≥3 次相同输入,核心逻辑/格式/约束符合度无随机偏离,一致性 ≥90% |
| 缺陷密度统计 | 累计 ≥10 次真实调用问题记录,核心功能故障率 <10%,无严重级缺陷 |

### 1.3 三星通过标准

- **低风险**(只读/文档/评估/写作辅助/流程指导):至少 2 个 E3-MD 案例,其中 ≥1 个经外部复核或来自非作者场景;关键价值主张均有对应产物;无未解决严重失败;证据与当前版本匹配。
- **高风险**(显著影响代码生成/架构决策/安全操作/外部交互):至少 3 个 E3-MD 案例,其中 ≥1 个来自真实用户或独立复核者;覆盖声明核心能力;涉危险操作须只读/脱敏/沙箱证明;不得仅凭作者自述给 ⭐⭐⭐。

### 1.4 无效证据(不能作为 E3-MD)

作者自述"本 skill 有效"、仅文本设计精巧的静态分析、模拟推演而非真实运行、GitHub star / 下载量 / 好评截图 / README 承诺 / 无产物的口头反馈。流行度不是结果证据。

### 1.5 边界

- 作者自证只能作弱证据(需更多案例数量或外部复核);独立复核者确认产物有效 = 强 E3。
- 从未被使用 / 无法提供执行轨迹 / 证据无法溯源到 skill 指令 / 仅靠自我评估 → ⭐⭐⭐ 不可达。
- 安全边界不突破:不得为收集证据执行危险命令、索取真实密钥、读取敏感私有数据;高风险 skill 宁可保持 ⭐⭐。

### 1.6 对 skill-doctor 自身

纯 Markdown,不因"是评估工具"豁免,但可通过 E3-MD 达 ⭐⭐⭐:证据是它评估其他 skill 的真实报告经独立复核后准确、可追溯、可操作(≥3 案例 + 独立复核记录 + 可追溯性 + 版本绑定)。禁止只靠自产报告自证。

### 1.7 报告展示

- 无 E2/E3 证据:优秀度 ⭐⭐ / 证据等级 E1 静态审计 / 标注"v3 证据门槛提升后的保守评级,非质量回退" / 升级路径"提交 E2 干跑证据或 E3 真实使用产物证据(E3-MD)"。
- 纯 Markdown 有 E3-MD:优秀度 ⭐⭐⭐ / 证据等级 E3-MD 真实使用产物审查 / 证据摘要(case 列表)。
- v2→v3 迁移:v2 历史评级 ⭐⭐⭐ → v3 当前评级 ⭐⭐,原因"v3 将结果保证纳入评级,当前缺少 E2/E3 证据",状态"待补证据,不是缺陷数量增加"。

## 2. 元工具「设计卓越」过渡标识

仅元工具类纯 Markdown skill(评估/规范其他 skill 的基础设施,如 skill-doctor 自身)可申请,用于暂未积累证据时避免"设计优秀但无可验证结果"被永久埋没:

- **形式**:不直接授予 ⭐⭐⭐,在 ⭐⭐ 基础上加「设计卓越」标识,标注"静态评审顶级,暂无运行实证",与有 E3 证据的 ⭐⭐⭐ 视觉/语义明确区分。永久不允许"无证据三星"。
- **准入**:经多人交叉评审,规则完备性 / 逻辑自洽性 / 生态通用性达顶级。
- **过渡**:临时状态,引导积累自身运行数据(评估准确率 / 缺陷召回率 / ≥10 次评估记录),最终走正式 E3-MD 路径升 ⭐⭐⭐。
- **三条红线**:范围不可泛化(仅元工具)、形式不可混同(与实证 ⭐⭐⭐ 区分)、状态不可永久(有升星指引)。
